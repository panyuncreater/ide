# ADR-004: COW（Copy-On-Write）内存模型

## Status

Accepted. 自项目初始采用，与 NaN-boxing 配合使用。

## Background

MiniLang 的数组和字典是引用语义（多个变量可共享同一堆对象）。当多个变量引用同一对象时，修改操作需要决定是否影响其他引用者：
- **深拷贝语义**：每次修改都复制，安全但性能差
- **引用语义**：共享修改，性能好但容易引发意外副作用
- **COW 语义**：仅在必要时复制，兼顾安全与性能

## Decision

采用 Copy-On-Write（写时复制）策略：

### 核心机制

1. **引用计数**：`RefCounted` 基类提供侵入式引用计数
   - 每个堆对象维护引用计数
   - 赋值/传参时增加引用计数（O(1)）
   - 作用域退出时减少引用计数

2. **独占检测**：修改前检查引用计数
   - `refCount == 1`：独占所有权，直接修改（零拷贝）
   - `refCount > 1`：共享所有权，先深拷贝再修改

3. **NaN-boxing 集成**：Value 中的堆指针指向 `RefCounted` 派生对象
   - 指针类型 tag（`0x7FF8`-`0x7FFB`）直接存储 48 位堆地址
   - 引用计数操作通过指针偏移访问对象头部的 `refCount_` 字段

### GC 补充

`GcManager` 管理循环引用检测：
- Mark phase：从根集合出发标记可达对象
- Sweep phase：回收未标记对象
- Cycle detection：处理引用计数无法解决的循环引用

### 安全约束

- 容器越界错误路径强制走 const 访问器，避免 COW 深拷贝
- Value 数组/容器强制 value-initialize 防止 NaN-box 未初始化内存被误判
- `std::unique_ptr` 管理深拷贝操作，防止 bad_alloc 泄漏

## Impact

- **性能**：大多数修改操作在独占所有权时零拷贝，显著减少内存分配
- **内存**：引用计数 8 字节/对象的开销，但避免了不必要的深拷贝
- **复杂度**：需要严格维护引用计数的一致性，泄漏或提前释放会导致崩溃
- **限制**：循环引用需要 GC 补充处理

## Alternatives

- **纯引用计数（无 COW）**：简单但每次修改都需深拷贝或引入别名问题
- **纯 GC（无引用计数）**：实现简单但有 GC 暂停问题，不适合教学场景的即时反馈
- **Region-based 内存管理**：适合编译器实现但对通用语言限制过大
