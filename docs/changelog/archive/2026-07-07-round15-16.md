## 2026-07-07 · 第十六轮架构优化：观察者模式解耦 + 三后端差分测试（OPT-1 / OPT-2）

### 概述

承接第十五轮三后端一致性审计，本轮针对用户提出的两项架构优化建议进行实施：(1) **OPT-1 GUI 与引擎层耦合风险**——`IdeController` 作为 Facade 暴露大量内部状态 API（`getVmCallStack`/`getVmGlobals`/`getVmStack` 等），多个面板通过 QTimer 500ms 轮询消费这些 API，CPU 开销高且响应滞后；(2) **OPT-2 三后端维护成本高**——每处语义变更需同步修改三条路径（Interpreter / StackVM / RegisterVM），AGENTS.md 记录的 10 类高频 Bug 模式中多数源于三后端不一致。本轮完成两项建议的核心子项：观察者模式替代轮询（保留 `IdeController` Facade，未拆分 `EngineFacade`+`GuiAdapter`，原因见下文决策）+ 模板化随机程序差分回归测试（10 类 × 11 套件共 368 个测试用例，固定种子可复现）。新增 11 个测试套件 / 368 个用例，全量 1709/1709 测试通过（186 秒）。

### 修改内容

1. **app/IdeController.h — vmStateChanged 观察者 API（OPT-1）**
   - 新增 `using VmStateChangedCallback = std::function<void()>;` + `addVmStateChangedListener(cb)` + `notifyVmStateChanged()`
   - 监听器存储在 `std::vector<VmStateChangedCallback> vmStateChangedListeners_`
   - `notifyVmStateChanged()` 先做 `auto snapshot = vmStateChangedListeners_;` 再迭代，防止回调内 add/remove 监听器导致迭代器失效
   - 所有 VM/调试状态变更点（vmStep/vmStepByMode/setVmBreakpoints/setVmBreakpointConditions/vmStop/vmReset/setBreakpoints/setBreakpointCondition/setupDebug）调用 `notifyVmStateChanged()` 通知订阅面板
   - **保持 inline**：MagicCommands.cpp（在 minilang_core 中）依赖 vmStep/vmReset 等内联符号，测试目标不链接 IdeController.cpp。改为非内联会导致链接错误。所有 VM 方法继续在头文件中实现，仅在末尾追加 `notifyVmStateChanged()` 调用

2. **app/IdeController.cpp — 信号桥接 + 删除非内联 VM 方法（OPT-1）**
   - 构造函数中 3 个信号→观察者桥接：
     - `connect(&vmStepper_, &VmStepper::vmRunPaused, this, [this](VmStepResult){ notifyVmStateChanged(); });` — VM RUN 异步执行暂停时通知
     - `connect(&debugCoord_, &DebugCoordinator::pausedAt, this, [this](int){ notifyVmStateChanged(); });` — 调试器断点暂停时通知
     - `connect(&workerMgr_, &WorkerManager::workerFinished, this, [this](bool){ notifyVmStateChanged(); });` — Worker 线程完成时通知
   - 删除 7 个非内联 VM 方法实现（vmStep/vmStepByMode/setVmBreakpoints/vmStop/vmReset/setBreakpoints/setBreakpointCondition），它们已改为 inline 在头文件中

3. **5 个面板订阅监听器 + QTimer 500ms→2000ms 降频（OPT-1）**
   - `gui/CallStackPanel.cpp` / `gui/VariableInspectorPanel.cpp` / `gui/BytecodeTracePanel.cpp` / `gui/MemoryModelPanel.cpp` / `gui/BreakpointConditionPanel.cpp`
   - 每个面板的 `setController(IdeController* controller)` 改为非内联实现（移到 .cpp）
   - QTimer 间隔从 500ms 改为 2000ms（降为 1/4 频率），作为兜底刷新机制（监听器即时通知 + 2s 兜底轮询双保险）

4. **tests/TestThreeEnginesFuzz.cpp — 三后端随机程序差分回归测试（OPT-2，新增 ~390 行）**
   - 11 个测试套件共 368 个用例（ArithmeticFuzz 60 / ControlFlowFuzz 40 / FunctionFuzz 40 / RecursionFuzz 30 / ClosureFuzz 30 / StringFuzz 30 / ArrayFuzz 30 / ClassFuzz 30 / ErrorPathFuzz 30 / LogicFuzz 30 / DeterministicBaseline 8）
   - 固定种子 `mt19937_64`（`kFuzzSeed = 0x4D4C416E67000000ULL`）保证可复现
   - `expectThreeAgree` 差分断言：Interpreter vs StackVM 严格断言，RegisterVM 编译失败时宽容跳过

5. **gui/ReplPanel.cpp — 修复预存 Bug：`finallyCount` 未声明标识符（P2-C）**

### 关键决策

1. **保留 `IdeController` Facade，未拆分 `EngineFacade` + `GuiAdapter`**：拆分需引入 Qt 信号适配层 + 调整所有面板的 `setController` 签名，影响面大且测试目标链接约束复杂
2. **纯 C++ 观察者（`std::function` 监听器）而非 Qt 信号槽**：`std::function` 监听器更轻量，测试目标无需 moc 依赖
3. **VM 方法保持 inline**：MagicCommands.cpp 依赖内联符号，保持 inline 是最低成本解决方案
4. **RegisterVM 编译失败宽容策略**：RegisterVM IR lowering 对 for 循环、部分数组操作支持不完整，严格断言会阻塞差分测试运行
5. **固定种子 + 模板化生成**：保证 CI 失败可复现 + 语法合法 + 执行有界

- 修改：5 个面板 `.h/.cpp`（setController 非内联 + QTimer 降频）
- 新增：`tests/TestThreeEnginesFuzz.cpp`（390 行，11 套件 368 用例）
- 修改：`gui/ReplPanel.cpp`（finallyCount 修复）
