## 已修复

### P1｜F2（B-004）REPL 跨行生成器恢复必然失败

- **根因**：`ReplPanel::executeLine` 每行新开 `std::async`（MSVC 每个 future 独立线程）；协程 fiber 在首次 `.next()` 所在线程登记 `ownerThread`，跨行恢复时线程必然不同，被 §3.8 防御以「协程不可跨线程恢复」拒绝。防御本身正确，与宿主逐行线程模型冲突。
- **修复**：新增 `gui/ReplTaskQueue.h`——常驻单线程 + FIFO，`start/post/stop` 幂等且可 join。`ReplPanel` 整个会话复用同一队列（首次执行惰性启动，析构停止并 join），任务经 `std::packaged_task`/future 投递，主线程仍以 QTimer 轮询取结果。跨行 fiber ownerThread 恒定。
- **回归**：`CoroutineSuspension.PersistentExecutorResumesGeneratorAcrossLines`——4 行跨行创建/恢复生成器输出 `2true`，并断言全部任务线程 id 为队列线程；既有 `CoroutineSuspension.CrossThreadResumeRejected` 保持通过（防御未被削弱）。
- **语义影响**：语言层零变化；宿主 REPL 由「每行一线程」改为「会话单线程」，代价为一个常驻空闲线程。

### P1｜F7（B-005）capi 插件卸载后宿主函数悬垂

- **根因**：`minilang_load_plugin` 注册的 HostThunk/HostFn 永久留在进程级 `HostFunctionRegistry`；`minilang_destroy` 仅 `FreeLibrary`/`dlclose` 卸载库。此后任一 context 调用同名函数即跳转已卸载代码页（跨 context UAF）。
- **修复**：`minilang_context` 记录本 context 注册的宿主函数（插件 init 期间的同步注册同样落入）；`HostFunctionRegistry` 新增按 `(name, fn, userdata)` 精确注销；`minilang_destroy` 先注销并 `delete` thunk，再卸载插件库。同名条目被其他 context 覆盖时不误删。注册表在 context 存活期间仍跨 context 可见，生命周期改为 context 归属（`minilang_capi.h` 契约同步，并注明销毁前不得有其他线程调用）。
- **回归**：`PluginTest.CApiRegisterFunctionUnregisteredOnDestroy`、`PluginTest.CApiDestroyKeepsOverridingRegistration`；`PluginTest.LoadPluginAndCall` 增加销毁后 registry 无 `mini_add` 残留断言。
- **语义影响**：C API 注册生命周期由「进程级永久」改为「context 存活期」；宿主若需跨 context 长期注册，须保持注册 context 存活。
