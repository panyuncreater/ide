# 已否决方案与重启条件（Spec）

> 记录“评估后不实施”的结论，防止同一分析被重复立项。每行必须有证据与**明确重启条件**；条件不成立时不再讨论。
> 已实施/已修复的方案不进本表（见 CHANGELOG）；开放缺陷与候选优化见 `docs/BACKLOG.md`。

| ID | 方案 | 结论与证据 | 重启条件 |
|----|------|-----------|---------|
| R-01 | StackVM/RegisterVM 实例字段内联缓存（IC） | 不实施。短 SSO 键 `unordered_map::find` 实测 5.8ns/次，IC 命中 0.8ns；field_access 基准收益上限约 2.5%，低于基准方差 2 倍。JIT 单态 IC 已覆盖；StackVM 三级缓存已覆盖调用/全局/方法分派。 | 对象模型改为 hidden-class 槽位化；或实测 `find` 因长字段名/大字段表退化。 |
| R-02 | GC 分配路径 thread_local 批量登记去锁 | 不实施。`slots_` 一致性要求分配/析构/collect 全程持锁；thread_local 缓冲会导致漏 sweep 或 GcOnly 模式 UAF，需 TSan 通道专验。 | 引入 TSan CI 门禁并可证明批量合并的一致性。 |
| R-03 | 实例字段 O(1) 读取（复用 `fieldSlotIndex`） | 不成立。`fieldSlotIndex` 只优化方法返回写同步，VM 字段读取同样是哈希查找；原“已 O(1)”前提与代码不符。 | 仅随 hidden-class/字段槽位化重构重启。 |
| R-04 | 行列元数据 RLE 压缩 | 不适用。line/col 已内联 Token，无独立数组可压；`columnAt` 已有 O(L) 缓存。 | 出现独立行列数组或元数据体积实测成为瓶颈。 |
| R-05 | 36 个存量教学面板迁移 `TeachingPanelBase` | 中止。主题回调在面板生命周期内从不触发（深色主题已移除、`setThemeMode` 仅启动调用一次）；迁移属零行为变化的大面积搅动。 | 主题切换在运行期重新可达，或基类出现真实共享行为。 |
| R-06 | 恢复深色主题/扩展主题回调 | 不实施。`Theme::setThemeMode(LIGHT)` 仅启动调用；15 个面板虽引用 `TeachingTheme` 但无动态主题路径。 | 产品重新提供运行期主题切换。 |
| R-07 | 条件断点 D3 三个子问题（入口快照/沙箱标志/缓存 slot 失配） | 误报或已被覆盖：SandboxGuard 16 类状态 RAII、VM 每求值全新临时 Interpreter、条件缓存按文本键控 AST。 | 出现可复现的新证据。 |
| R-08 | 单边修改 upvalue 快照语义“对齐 Lua/JS” | 禁止。实测三后端本已一致（快照语义）；单边改会制造新分歧。 | 三后端同步引入共享 upvalue cell 的架构级 ADR。 |
| R-09 | JIT 与 VM 的“跨后端帧协议” | 前提不实。JIT 与 VM 无帧互操作；JIT 零 VM 引用，OSR/反优化均在 JIT 块内。真实跨块协议是 `JitContext.callImportSlots`。 | 设计出现 JIT/VM 混执行帧时。 |
| R-10 | “VM 真挂起（D.5）”历史注释 | 错误。ADR-007 落地前四后端均为重放；单后端升级会制造副作用次数分歧。 | 不重启；以 ADR-007 为准。 |
| R-11 | macOS 立即启用协程真挂起 | 不实施。ucontext 例程已 deprecated，发布矩阵 mac job 仅编译不跑测试，无行为验证通道。 | 补齐 macOS 测试门禁并可运行协程语义锁。 |
| R-12 | 多槽 GC 回调 / 全活跃 owner 根集合并 | 暂不实施。根集合并需在触发线程读取其他解释器的 `globalEnv_/callStack_`，GUI 存在主线程与 Worker 并存，跨线程同步风险大于收益；已用 `Isolated` + 面板守卫闭环。 | 宿主模型出现多个常驻解释器并存。 |
| R-13 | JIT 跨运行磁盘块缓存 | 暂不实施。进程内块缓存（ADR-008）已覆盖同源码重复运行；磁盘持久化需键代际与格式稳定协议。 | 需要跨进程复用且键结构稳定后立项。 |
| R-14 | 预编译模块可变导出快照的边角统一（循环导入/`.minic`） | 暂不实施。循环导入未 detach、`.minic` 无 AST 变量集，均保持共享；仅极边缘/IDE 专用场景，现有测试未覆盖该可观测差异。 | 出现用户可见分歧或预编译模块进入常规路径。 |
| R-15 | 栈式 VM 启用复制传播/CSE | 不实施。CSE 替换后续指令对 dest vreg 的引用，与栈式 VM 的栈语义冲突；DCE 已通过 `isPureCompute` 守卫安全启用。见 ADR-003。 | 栈式后端改为非栈式求值模型。 |
| R-16 | stepCallback 在错误路径通知 | 不实施。三后端均不在错误路径触发“指令成功执行”事件；BUG-016 已审计为误报。GUI 通过返回码 + `hasError_` 双重检测。 | 调试器协议要求错误路径也产生步进事件。 |
| R-17 | NaN-box `fromPtr` 高位指针改为堆包装 | 不实施。x86-64 用户空间虚拟地址高 16 位为 0 由硬件规范保证；abort 是防御性最后防线，实际不可触发。改造需新增类型 + 20+ 处 `asPtr` + 三后端同步。 | 支持高位地址的硬件/平台进入支持矩阵。 |
| R-18 | 拆分 `Bytecode.h` 以缩短重编译链 | 不实施。PCH 仅含标准库头，配置正确；`BytecodeChunk` 被 30+ .cpp 直接 include 是 C++ 依赖管理固有行为。彻底解决需 PIMPL，重构成本高于收益。 | 核心头变更频率显著上升或增量编译成为瓶颈。 |

## 维护规则

1. 新增一行前先在本表检索同一方案；重复立项直接引用 ID。
2. 结论必须带可复核证据（基准数据、代码位置或回归测试）；“感觉收益低”不算证据。
3. 重启条件必须可观测；条件成立时先更新本行状态，再进 `docs/BACKLOG.md` 立项。
