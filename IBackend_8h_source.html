35// ============================================================
36// IBackend 后端抽象接口（ARCH-09）
37// ============================================================
38// 设计目标：为 MiniLang 的两种执行后端（Interpreter 树遍历后端、
39// VM 字节码栈机后端）提供统一的抽象基类，使上层（IdeController /
40// WorkerManager）可通过 IBackend* 操作公共能力，便于未来替换或
41// 新增后端（如纯编译到 WASM、JIT 后端等）。
42//
43// 设计原则：
44// 1. 只抽象签名完全一致的方法 — 避免引入适配器层增加复杂度
45// 2. 执行入口（execute）不纳入接口 — Interpreter 输入 Block（AST），
46// VM 输入 CompileResult（字节码），输入类型根本不同，强行统一
47// 会牺牲类型安全。执行入口由具体后端类提供。
48// 3. 单步执行不纳入接口 — Interpreter 是 AST 节点级单步（由
49// DebugController 在 visit 回调中实现），VM 是指令级单步
50// （stepOnce），粒度不同。
51//
52// 已纳入接口的方法（5 个回调/诊断/错误查询方法，签名完全一致）：
53// - setOutputCallback：print 语句输出回调
54// - setInputCallback：input 函数输入回调
55// - getDiagnostics：错误/警告诊断包（共享 common/Diagnostic.h 类型）
56// - hasError：是否发生错误（P2-12，统一错误查询，从 diagnostics_ 派生）
57// - getLastError：获取最后一条错误消息（P2-12，从 diagnostics_ 派生）
58//
59// 未来扩展方向：
60// - IInterpreterBackend 子接口：executeRepl / saveReplState /
61// restoreReplState / setModuleLoader / setDebugger / evaluateCondition
62// - IVmBackend 子接口：initExecution / stepOnce / isFinished /
63// getStack / getGlobals / getCurrentIP / getCurrentLine / getFrameCount
64//
65// 与 ARCH-11（IdeController Facade 拆分）的关系：
66// ARCH-11 已通过 WorkerManager / VmStepper 持有具体后端类型实现解耦，
67// 本接口进一步提供类型抽象层。IdeController 当前不直接持有后端，
68// 故本接口主要作为类型契约和未来扩展点存在。

90 /// 是否发生错误（P2-12 统一错误查询）

95 /// 获取最后一条错误消息（P2-12 统一错误查询）
96 /// 从 diagnostics_ 派生，消除各后端独立的 lastError_ 字段冗余。
97 /// 返回**原始消息文本**（不含 [来源] 级别 (行 X) 前缀），保证三后端
98 /// （Interpreter/VM/RegisterVM）返回相同消息——这是三后端一致性测试
99 /// （TestThreeEnginesConsistency）的依赖。IDE 显示如需带位置信息，
100 /// 应直接遍历 getDiagnostics().all() 调用 Diagnostic::format()。
101 /// @return 最后一条 Error 级别诊断的 message 字段；无错误返回空字符串
102 virtual std::string getLastError() const {
103 const auto& diags = getDiagnostics().all();
104 for (auto it = diags.rbegin(); it != diags.rend(); ++it) {
105 if (it->isError())
106 return it->message;
107 }
108 return {};
109 }
110
111 /// 获取最后一条错误的源码行号（P2-12 统一错误查询）
112 /// 从 diagnostics_ 派生，消除各后端独立的 lastErrorLine_ 字段冗余。
113 /// @return 最后一条 Error 级别诊断的 line 字段；无错误返回 0
114 virtual int getLastErrorLine() const {
115 const auto& diags = getDiagnostics().all();
116 for (auto it = diags.rbegin(); it != diags.rend(); ++it) {
117 if (it->isError())
118 return it->line;
119 }
120 return 0;
121 }

124// ============================================================
125// IVmBackend — VM 类后端子接口（P1-5 fix）
126// ============================================================
127// 设计目标：为支持单步执行的 VM 类后端（StackVM / RegisterVM）提供统一的
128// 步进与状态检视接口。JITBackend 不实现此接口（JIT 一次性编译执行本地代码，
129// 不支持指令级单步）。
130//
131// 与 IBackend 的关系：
132// - IVmBackend 继承 IBackend，拥有 IBackend 的全部回调/诊断方法
133// - 额外提供 8 个步进/检视方法，签名在 StackVM 与 RegisterVM 间完全一致
134// - 上层（VmStepper / ExecutionTraceRecorder / 调试面板）可通过 IVmBackend*
135// 统一操作两种 VM 后端，无需模板化或类型分发
136//
137// initExecution 不纳入接口：
138// StackVM 输入 CompileResult，RegisterVM 输入 RegisterCompileResult，
139// 输入类型不同。调用方需用具体类型调用 initExecution，之后通过 IVmBackend*
140// 进行步进和检视。
141//
142// @since P1-5
143
144/// VM 调用栈帧条目（IVmBackend::getCallStack 返回类型）
145/// StackVM 与 RegisterVM 共享同一结构：函数名 + 当前行号 + 指令指针。
146/// 不含 locals（需通过具体子类的 getFrameLocalsAt 单独查询，避免每个后端
147/// 自行实现 locals 反查逻辑）；不含 depth（调用方按 vector 索引推导）。
148/// @since P1-5 扩展（getCallStack 纳入接口）
149struct VmCallStackEntry {
150 std::string functionName; // "main" 或函数名
151 int line = 0; // 当前源码行号（1-based，0=无位置信息）
152 size_t ip = 0; // 当前指令指针
153};
