1/**
2 * @file compiler/jit/JIT.h
3 * @brief JIT 后端：基于 asmjit 的第四套执行引擎（R138-R141 演进）。
4 *
5 * 将 BytecodeChunk 编译为本地机器码（x86-64），直接在 CPU 上执行。
6 * 与 StackVM 共享编译管线（输入 BytecodeChunk），是 StackVM 的"加速器"。
7 *
8 * 阶段 1 PoC 范围（R138）：
9 * - 仅处理 mainChunk（不支持函数调用）
10 * - 仅支持整数算术子集：OP_INT / OP_ADD / OP_SUBTRACT / OP_MULTIPLY /
11 * OP_NEGATE / OP_PRINT / OP_POP / OP_RETURN / OP_NULL / OP_TRUE / OP_FALSE
12 * - JIT 内部以 raw int64_t 表示 Value（不做 NaN-boxing），简化 PoC
13 *
14 * 阶段 2a 扩展范围（R139）：
15 * - 控制流：OP_JUMP / OP_JUMP_IF_FALSE / OP_LOOP（绝对偏移跳转，两遍扫描绑定 Label）
16 * - 全局变量 slot：OP_DEFINE_GLOBAL / OP_GET_GLOBAL / OP_SET_GLOBAL
17 * - 比较指令：OP_EQUAL / OP_NOT_EQUAL / OP_LESS / OP_GREATER /
18 * OP_LESS_EQUAL / OP_GREATER_EQUAL（cmp + setcc，结果为 0/1）
19 * - 逻辑取反：OP_NOT（test + sete，结果为 0/1）
20 *
21 * 阶段 2a+ 算术完善（R140）：
22 * - 整数除法：OP_DIVIDE（cqo + idiv，截断向零）
23 * - 整数取模：OP_MODULO（cqo + idiv，余数在 rdx）
24 * - 除零错误路径：test + jz → jitReportError → jmp epilogue
25 *
26 * 阶段 2b 函数调用（R141，后续版本持续扩展）：
27 * - 所有 chunk（mainChunk + functionChunks）编译到一个 CodeHolder
28 * - 每个 chunk 对应一个入口 Label，OP_CALL 用 jmp targetLabel
29 * - 局部变量：OP_GET_LOCAL / OP_SET_LOCAL（r13 = basePointer，[r13 - slot*8]）
30 * - 函数调用：OP_CALL（保存调用者帧 → 设置新 r13 → jmp 函数 Label）
31 * - 函数返回：OP_RETURN（恢复调用者帧 → jmp 返回地址；mainChunk return 跳 epilogue）
32 * - 闭包创建：OP_CLOSURE（R156 起支持 upvalue 捕获，含 closed/open 两种状态）
33 * - 闭包值调用：OP_CALL_EXPR（R155 实现，含 upvalue 绑定与默认参数补全）
34 * - 方法调用：OP_METHOD_CALL / OP_SUPER_CALL（R149 实现，含 init 自动调用与字段 writeBack）
35 * - 默认参数：编译期收集 defaultConstIndices，运行时按 missingCount 补全（R149/R155）
36 * - 递归深度限制：RuntimeLimits::MAX_FRAMES（256），超出报 recursion-depth-exceeded
37 *
38 * 阶段 2c 浮点原生与类型反馈（R152）：
39 * - 浮点原生：发射 SSE2 指令（movsd/addsd/subsd/mulsd/divsd），三层分派
40 * （INT 原生 → FLOAT 原生 → C++ helper 兜底），避免浮点走 C++ 辅助函数调用开销
41 * - 类型反馈：per-chunk TypeFeedback 计数器，重编译时决策 INT/FLOAT 特化策略
42 *
43 * 阶段 2d 异常处理（R162）：
44 * - try/catch/throw 结构化异常处理（OP_TRY_BEGIN/OP_TRY_END/OP_THROW）
45 * - finally 块与 break/continue 续跳（OP_PUSH_JUMP_TARGET/OP_FINALLY_END）
46 * - C++ 辅助函数 jitThrow 实现栈展开：搜索 tryStack_ → 截断操作数栈 → 跨帧传播
47 * - 跨帧异常传播：弹出 JitFrame、关闭 upvalue、恢复 r13/r15
48 * - JIT 代码通过 lea label 获取 catch 块绝对地址，jitThrow 返回该地址供 jmp
49 *
50 * GC 集成（P2-9 fix，R166）：
51 * - JIT 持有的 Value 引用（操作数栈/帧栈/全局槽位）以 NaN-boxing raw bits 表示，
52 * 未注册为 GC roots。若 JIT 执行期间 Interpreter 的增量 GC 回调被触发
53 * （jitBuildArray 等 helper 分配容器累计达 8192 阈值），会以不完整 roots 集
54 * 误回收 JIT 存活容器，导致 UAF。
55 * - 解决方案：JITBackend::execute() 入口构造 GcManager::CallbackSuppressor，
56 * 原子保存并置空 gcTriggerCallback_，析构时恢复。JIT 期间增量 GC 被完全抑制，
57 * 产生的循环引用孤岛由下一轮 Interpreter execute() 入口的兜底 collectCycle 回收
58 * （跨 execute 边界自动清理）。
59 * - 未实现 safepoint 轮询机制（在 OP_LOOP 回边处轮询 GC 请求标志并收集 JIT roots）：
60 * 当前方案对教学场景足够（JIT 执行短任务，GC 延迟到下一轮 Interpreter 执行），
61 * 长期运行场景的内存峰值可由 Interpreter 兜底回收控制。
62 *
63 * 尚不支持（截至 R166）：
64 * - 运行时错误不可捕获：除零/溢出/类型错误等 runtimeError 不触发 try/catch
65 * （与 StackVM 行为一致：try/catch 仅捕获显式 throw，不捕获运行时错误）
66 * - ARM64 移植（当前仅 x86-64）
67 *
68 * 教学价值：
69 * - 展示 JIT 编译原理：字节码 → 本地代码的直接映射
70 * - 与 StackVM dispatch loop 对比，演示 switch-based 解释执行 vs 本地代码性能差异
71 * - 展示寄存器分配、常量折叠（内联）、调用约定、跳转标签绑定等 JIT 核心概念
72 *
73 * 寄存器分配（R141 更新）：
74 * - r12 = JitContext* ctx（callee-saved，跨调用保留）
75 * - r13 = current frame basePointer（callee-saved，R141 新增，指向当前函数帧的第一个参数）
76 * - r15 = operand stack top（callee-saved，操作数栈顶，向低地址增长）
77 * - rax/rcx/rdx = 临时寄存器（算术运算、调用参数、比较结果）
78 * - rsp = 原生栈（仅用于函数调用 shadow space）
79 *
80 * 栈帧布局（rbp 相对寻址）：
81 * [rbp] = saved rbp
82 * [rbp-8] = saved r12
83 * [rbp-16] = saved r13
84 * [rbp-24] = saved r14
85 * [rbp-32] = saved r15
86 * [rbp-40] = operand stack base（r15 初始值，空栈）
87 * ... = operand stack（向下增长，8KB = 1024 值，R141 扩大以支持函数调用）
88 *
89 * JitContext 内存布局（JIT 代码通过 r12 + offset 访问）：
90 * offset 0 : outputCallback (8B, std::function*)
91 * offset 8 : hasError (8B, bool*)
92 * offset 16 : errorBuffer (8B, std::string*)
93 * offset 24 : globalSlots (8B, int64_t* 元素数组首地址) — R139 新增
94 * offset 32 : frames (8B, JitFrame* 帧栈数组) — R141 新增
95 * offset 40 : frameCount (8B, size_t* 当前帧深度指针) — R141 新增
96 * offset 48 : stackTop (8B, int64_t* 操作数栈顶指针) — R146 新增
97 * offset 56 : classInfoPtr (8B, unordered_map<string,JitClassInfo>*) — R148 新增
98 * offset 64 : pendingFieldOrderPtr (8B, vector<string>*) — R148 新增
99 * offset 72 : methodEntryPtr (8B, void* 方法入口地址邮箱) — R149 新增
100 * offset 80 : methodLocalCount (8B, int64_t 方法 localCount 邮箱) — R149 新增
101 * offset 88 : methodEntriesPtr (8B, unordered_map<string,JitMethodInfo>*) — R149 新增
102 * offset 96 : callerBp (8B, int64_t* 调用者 r13 邮箱) — R149 新增
103 * offset 104 : chunkCallCounts (8B, uint64_t* per-chunk 调用计数数组) — R150 新增
104 * offset 112 : hotThresholds (8B, uint64_t* per-chunk 热点阈值数组) — R151 新增
105 * offset 120 : recompiledFlags(8B, uint64_t* per-chunk 重编译标志数组) — R151 新增
106 * offset 128 : typeFeedback (8B, TypeFeedback* per-chunk 类型反馈数组) — R152 新增
107 * offset 136 : backendPtr (8B, JITBackend* this 指针) — R152 新增
108 * offset 144 : lastMutatedReceiverPtr (8B, int64_t* 嵌套左值赋值链中转邮箱) — R154 新增
109 * offset 152 : funcEntriesPtr (8B, unordered_map<string,JitMethodInfo>*) — R155 新增
110 * offset 160 : currentBp (8B, int64_t* 当前帧 basePointer r13) — R156 新增
111 * offset 232 : memberGetICPtr (8B, MemberGetInlineCacheEntry*) — R160 新增
112 * offset 240 : globalsPtr (8B, unordered_map<string,Value>*) — R162 新增
113 * JIT 代码访问 globalSlots[slot]: mov rcx, [r12+24]; mov rax, [rcx + slot*8]
114 * JIT 代码访问帧栈: mov rax, [r12+32]; mov rcx, [r12+40]; mov rcx, [rcx]
115 * R146 数组辅助函数访问 JIT 栈: JIT 代码在调用前 mov [r12+48], r15 更新栈顶指针，
116 * 辅助函数通过 ctx->stackTop 读写栈，调用后 JIT 代码 mov r15, [r12+48] 恢复
117 *
118 * R141 帧栈布局（JitFrame 数组，R149 扩展为 72 字节）：
119 * [frames + idx*72 + 0] : callerBp (int64_t*, 调用者 r13)
120 * [frames + idx*72 + 8] : callerSp (int64_t*, 调用者 r15，调用前状态)
121 * [frames + idx*72 + 16] : returnAddr (void*, 返回地址)
122 * R149 方法调用扩展字段（isMethodCall=true 时有效）：
123 * [frames + idx*72 + 24] : receiverSlotPtr (int64_t*, 接收者 slot 地址，null=无 writeBack)
124 * [frames + idx*72 + 32] : methodFieldOrder (const std::vector<std::string>*, 方法 chunk 的 fieldOrder)
125 * [frames + idx*72 + 40] : methodBp (int64_t*, 方法帧 basePointer = this 位置)
126 * [frames + idx*72 + 48] : isMethodCall (int64_t, 0/1)
127 * [frames + idx*72 + 56] : isInitCall (int64_t, 0/1)
128 * [frames + idx*72 + 64] : fieldCount (int64_t, 方法 chunk 的字段数量)
129 *
130 * @see IBackend BytecodeChunk VM Compiler
131 * @since R138
132 */

160/// R152: 类型反馈计数器（per-chunk）
161/// 在算术指令的 genericXXX 路径递增对应计数器，重编译时根据反馈决定特化策略：
162/// - intCount == totalArithOps && otherCount == 0 → INT 特化（跳过 emitCheckInt）
163/// - floatCount > 0 && otherCount == 0 → FLOAT 特化（未来支持）
164/// - otherCount > 0 → 不特化（保持类型分派）
165struct TypeFeedback {
166 uint64_t intCount = 0; ///< INT 类型观测次数（emitCheckInt 通过的次数，可选统计）
167 uint64_t floatCount = 0; ///< FLOAT 类型观测次数（genericXXX 路径递增）
168 uint64_t otherCount = 0; ///< 其他类型（STRING/OBJ/NULL）观测次数（genericXXX 路径递增）
169};

171/// R158: JIT 分层编译 Tier 枚举
172/// 实现 V8 风格的分层编译（Tiered Compilation）：
173/// - Tier 0 (Interpreter): 树遍历解释器，快速启动，无 JIT 开销
174/// - Tier 1 (Baseline): 非特化 JIT，快速编译，包含类型反馈收集
175/// - Tier 2 (Specialized): 特化 JIT，基于类型反馈的 INT/FLOAT 特化版本
176/// 升级链：Tier 0 → Tier 1 → Tier 2（基于热点计数）
177/// 降级链：Tier 2 → Tier 1（反优化 deoptimization，类型反馈失效时）
178enum class JitTier : uint8_t {
179 Interpreter = 0, ///< Tier 0: 解释器（JIT 不直接管理，仅作为概念层）
180 Baseline = 1, ///< Tier 1: Baseline JIT（非特化版本，含类型反馈收集）
181 Specialized = 2, ///< Tier 2: 特化 JIT（INT/FLOAT 特化版本）
182};

184/// R158: OSR 栈帧快照（真正 OSR 栈帧迁移用）

190 int64_t* frameSp = nullptr; ///< OSR 触发时的 r15（操作数栈顶）
191};

204/// JIT 运行时帧（R141 新增，用于函数调用帧栈管理）
205/// 每个 JitFrame 记录调用者的状态，供 OP_RETURN 恢复。
206/// R149 扩展为 72 字节，添加方法调用 writeBack 相关字段。
207/// 字段顺序固定，JIT 代码通过硬编码偏移访问（72 字节 per frame）。
208struct JitFrame {
209 int64_t* callerBp = nullptr; ///< offset 0: 调用者 basePointer（r13）
210 int64_t* callerSp = nullptr; ///< offset 8: 调用者操作数栈顶（r15，调用前状态）
211 void* returnAddr = nullptr; ///< offset 16: 返回地址（JIT 代码内的指令地址）
212 int64_t* receiverSlotPtr = nullptr; ///< offset 24: 接收者 slot 地址（null=无 writeBack，如临时表达式）
213 const std::vector<std::string>* methodFieldOrder =
214 nullptr; ///< offset 32: 方法 chunk 的 fieldOrder（writeBack 时按序同步字段槽）
215 int64_t* methodBp = nullptr; ///< offset 40: 方法帧 basePointer（this 位置，writeBack 时读取修改后的 this）
216 int64_t isMethodCall = 0; ///< offset 48: 是否方法调用（1=是，需 writeBack）
217 int64_t isInitCall = 0; ///< offset 56: 是否 init 调用（1=是，返回 this 而非返回值）
218 int64_t fieldCount = 0; ///< offset 64: 方法 chunk 的字段数量
219};

399/// R160 → PIC 升级: Per-call-site polymorphic inline cache for OP_MEMBER_GET
400/// 4 路多态 inline cache：缓存最多 4 个 (Instance 内部指针, 字段 Value 指针) 对。
401/// 当同一 call site 遇到超过 4 种不同 Instance 类型时，标记为 megamorphic，
402/// 后续所有查找直接走慢速路径（unordered_map lookup），避免缓存抖动。
403///
404/// 安全性论证（同原 monomorphic 版本）：
405/// - cachedInstancePtr 是 InstanceData 的原始地址（从 NaN-boxed Value 的低 48 位提取）
406/// - cachedFieldValuePtr 指向 unordered_map<string,Value> 中某个 node 的 value
407/// - C++ 标准：unordered_map 的 node 在 erase 之前地址稳定（rehash 不移动 node）
408/// - MiniLang 语义：字段只在 OP_INIT_FIELD 时插入，不会被 erase → 指针始终有效
409/// - COW 安全性：若 Instance 被 COW 复制，receiver 的 InstanceData 指针会改变
410/// （指向新副本），cache 自动 miss（cachedInstancePtr != 实际指针），不会读到旧数据
411/// - 字段值修改：若字段值被 OP_MEMBER_SET 修改，cachedFieldValuePtr 指向的 Value
412/// 会被原地更新（unordered_map operator[] 修改现有 node 的 value，不 invalidate 指针）
413struct MemberGetInlineCacheEntry {
414 static constexpr int kPICSlots = 4; ///< PIC 槽位数（4 路多态）
415
416 struct Slot {
417 const void* cachedInstancePtr = nullptr; ///< cache key: InstanceData 原始地址
418 const Value* cachedFieldValuePtr = nullptr; ///< cache value: 字段 Value 指针（直接读取）
419 };
420
421 Slot slots[kPICSlots]; ///< 4 路 PIC 槽位
422 uint8_t slotCount = 0; ///< 已使用的槽位数（0~kPICSlots）
423 bool megamorphic = false; ///< 超过 kPICSlots 种类型后置 true，永久走慢速路径
424
425 /// 查找 instPtr 对应的缓存字段指针（命中返回 Value*，未命中返回 nullptr）
426 const Value* lookup(const void* instPtr) const {
427 for (uint8_t i = 0; i < slotCount; ++i) {
428 if (slots[i].cachedInstancePtr == instPtr)
429 return slots[i].cachedFieldValuePtr;
430 }
431 return nullptr;
432 }
433
434 /// 插入新条目。若已满则标记 megamorphic 并返回 false。
435 bool insert(const void* instPtr, const Value* fieldPtr) {
436 if (megamorphic)
437 return false;
438 // 检查是否已存在（避免重复插入）
439 for (uint8_t i = 0; i < slotCount; ++i) {
440 if (slots[i].cachedInstancePtr == instPtr) {
441 slots[i].cachedFieldValuePtr = fieldPtr; // 更新
442 return true;
443 }
444 }
445 if (slotCount >= kPICSlots) {
446 megamorphic = true; // 类型过多，退化为 megamorphic
447 return false;
448 }
449 slots[slotCount].cachedInstancePtr = instPtr;
450 slots[slotCount].cachedFieldValuePtr = fieldPtr;
451 ++slotCount;
452 return true;
453 }
454};

465/// 方法调用 Inline Cache：缓存 (className, methodName) → JitMethodInfo* 的解析结果。
466/// 避免每次方法调用都沿继承链做 string 拼接 + map lookup。

471
472 struct Slot {
473 const char* classNamePtr = nullptr; ///< cache key: receiver.className() 的内部指针
474 const JitMethodInfo* method = nullptr; ///< cache value: 解析到的方法信息
475 };
476
477 Slot slots[kSlots];
478 uint8_t slotCount = 0;
479 bool megamorphic = false;
480

482 for (uint8_t i = 0; i < slotCount; ++i) {
483 if (slots[i].classNamePtr == classNamePtr)
484 return slots[i].method;

487 }
488

506 }
