3// ============================================================
4// RefCounted.h — 侵入式引用计数基类（PERF-12 基础设施）
5// ------------------------------------------------------------
6// 为 Value 的堆类型数据提供引用计数，替代 shared_ptr。
7// 配合 NaNBox 使用：Value 仅持有 8 字节 NaNBox，指针类型
8// 存储原始 RefCounted* 指针，由 Value 的拷贝/移动/析构
9// 手动管理引用计数。
10//
11// 设计要点：
12// - refCount 为 mutable atomic，支持 const 对象的 addRef/release
13// - type 为 const ValueType，构造时设定后不可变
14// - 拷贝构造重置 refCount=1（克隆出新对象，不继承原引用计数）
15// - 拷贝赋值删除（避免意外复制引用计数）
16// - 虚析构支持派生类正确释放
17//
18// 已知限制：环形容器泄漏（#9 文档化）
19// ---------------------------------------------
20// 侵入式引用计数 *不* 进行循环收集。当用户构造自引用容器时，
21// 引用计数永远不会降到 0，导致内存泄漏直至进程退出。例如：
22//
23// var a = [];
24// a.append(a); // a → a 形成自环，refCount ≥ 2 永不归零
25//
26// var d = {};
27// d.self = d; // 字典自引用，同上
28//
29// var x = [];
30// var y = [x];
31// x.append(y); // x ⇄ y 双向循环
32//
33// 设计权衡：
34// - 循环收集（如 Python 的 gc 模块、JavaScript 的 mark-sweep）
35// 需要独立追踪容器图并周期性扫描，开销和复杂度显著高于纯引用计数。
36// - 闭包场景已通过 weak_ptr<Environment> 显式打破 ClosureData →
37// Environment → ClosureData 的循环（见 Value.h 的 ClosureData），
38// 因为该循环是语言语义固定模式，可静态消除。
39// - 用户层容器自引用是动态行为，无法静态消除；MiniLang 作为教学/
40// 嵌入式语言，进程退出时由 OS 回收全部内存，可接受一次性泄漏。
41//
42// 缓解措施（语言层）：
43// - 解释器/VM 在每次程序执行结束后 resetState()，丢弃所有根引用，
44// 对于 *非循环* 的容器图足以释放；循环容器则依赖 OS 退出回收。
45// - 长期运行宿主（如 IDE 持续执行用户代码）可通过限制单次执行的
46// 内存上限或定期重启 VM 实例来控制累积泄漏。
47//
48// 缓解措施（未来扩展）：
49// - 若需支持长生命周期 + 用户可构造循环，可引入分代/增量 mark-sweep
50// 作为 refcount 的补充：周期性扫描 ArrayData/DictData/InstanceData
51// 节点，标记从根集可达的对象，释放不可达的循环孤岛。
52// - 实现位置：新增 GcManager 单例，持有所有 RefCounted 容器节点的
53// 弱引用列表，VM 主循环每 N 条指令触发一次扫描。
54// ============================================================

100 /// 增加引用计数（relaxed 内存序， sufficient for refcounting）
101 void addRef() const { refCount.fetch_add(1, std::memory_order_relaxed); }
102
103 /// 内存序说明：fetch_sub 使用 release——release 半序保证本线程对该对象内容的所有
104 /// 写操作在引用计数递减"发布"前完成。归零路径（即将 delete 本对象）在 delete 前
105 /// 插入 acquire 全线程栅栏，保证其他线程此前对该对象已"发布"的写操作对当前线程
106 /// 可见，从而 delete（在另一线程/本线程）读到一致状态。这是 shared_ptr 同款惯用法：
107 /// 非归零路径（绝大多数 decrement）只需 release 半序，省去 acq_rel 的 acquire 半序，
108 /// 堆值密集代码（字符串拼接/容器元素搬运/字段赋值）每条指令减少 1 次强同步。
109 /// 减少引用计数，若降为 0 则自删除
110 void release() const {
111 if (refCount.fetch_sub(1, std::memory_order_release) == 1) {
112 std::atomic_thread_fence(std::memory_order_acquire);
113 delete this;
114 }
115 }
