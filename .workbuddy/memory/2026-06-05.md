## Bug修复 - 格式化多次使用后代码丢失

**根因**：两个 Formatter bug 叠加，导致重新解析时 ParseError → synchronize() 吞掉后续 `}` → 整块代码丢失

1. **formatBlock 给复合语句加 `;`**：`if/while/for/fun/class` 已以 `}` 结尾，再加 `;` 产生 `};`。重解析时 `expressionStatement()` 把 `;` 当表达式起始 → ParseError
2. **formatIfStmt 错误包装 else-if**：`else if` 被输出为 `else { if ... };`，而非 `else if ...`

**修复**：
- 新增 `isSelfTerminating()` 辅助函数，判断 NODE_IF_STMT/WHILE/FOR/FUN/CLASS
- `formatBlock` 和 `formatClassDecl` 对自终止语句不加 `;`
- `formatIfStmt` 检查 elseBranch 是否为 NODE_IF_STMT，直接输出 `else if ...`
- `formatNode` 从 dynamic_cast 链改为 switch(nodeType) 分发

## 优化修复 Round 6（7项）

### P2: Parser assignment/call 仍用 dynamic_cast

### P2: visitMethodCall writeBack 仅支持 VarRef

## Bug修复 Round 8（4项）

### Bug1: 逻辑运算符 &&/|| 未实现
- Lexer 不识别 `&` 和 `|` 字符
- 新增 `case '&':` 和 `case '|':` 分支，`&&` → TK_AND，`||` → TK_OR
- 单个 `&` 或 `|` 报错提示使用 `&&` 或 `||`
- Parser/Interpreter/VM/Compiler 无需改动（已有 and/or 支持）

### Bug2: 函数名称不能自定义
- `funDecl()` 的 `consume(TK_IDENTIFIER)` 不接受类型关键字（dict/array/int/float/string/bool）
- 新增 `consumeIdentifierOrType()` 方法，允许类型关键字作为函数名/类名
- `classDecl()` 中类名也改用 `consumeIdentifierOrType()`
- `classDecl()` 新增裸方法定义支持：`methodName() {}`（无需 `fun` 关键字）

### Bug3: 运行报错不能一次性检查完
- `Parser::parse()` catch ParseError 后调用 synchronize() 但吞掉错误
- 新增 `errors_` 向量和 `getErrors()`/`hasErrors()` 接口收集所有错误
- `ide.cpp` 的 `runParser()` 显示所有收集到的错误
- `onRun()`/`onDebug()`/`onFormat()`/`onShowBytecode()` 全部改用新机制

### Bug4: 面向对象方法修改字段丢失
- 方法中直接修改字段（如 `count = count + 1`）只更新方法环境，不更新 `this` 对象
- 根因：字段被复制为方法环境的局部变量，赋值不反映到 `this.fields`
- 修复：方法/构造函数执行后，遍历 `obj.fields` 同步方法环境变量回 `this` 对象
- 三处修复：visitMethodCall 类方法、visitFunCall 构造函数 init、visitVarDecl 无参构造 init
