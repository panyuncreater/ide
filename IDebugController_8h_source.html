2 * @file common/IDebugController.h
3 * @brief 调试控制器抽象接口（P1-4 调试系统统一）。
4 *
5 * 为 DebugController（Interpreter 路径，跨线程阻塞模型）与
6 * VmStepper（VM 路径，主线程 QTimer 异步模型）提供统一的类型契约。
7 *
8 * 设计原则（与 IBackend.h 一致）：
9 * - 只抽象签名完全一致的方法 — 避免引入适配器层增加复杂度
10 * - 步进操作不纳入接口 — DebugController 用 condition_variable 阻塞 worker 线程，
11 * VmStepper 用 QTimer 异步分批，调用语义根本不同
12 * - 状态快照查询不纳入接口 — 返回类型不同（Value vs VariableSnapshot）
13 * - 内部检查 hook 不纳入接口 — 输入类型不同（ASTNode* vs int line）
14 * - 单断点增删不纳入接口 — API 形态不同（增量 vs 批量）
15 *
16 * 已纳入接口的方法（29 个，分 4 类）：
17 * - 断点配置（13）：setBreakpoints / setBreakpointKind / setLogpointMessage /
18 * setFunctionBreakpoint / removeFunctionBreakpoint / setFunctionBreakpoints /
19 * setFunctionBreakpointCondition / setExceptionBreakpointEnabled /
20 * setWatchpoint / removeWatchpoint / clearWatchpoints /
21 * setLogCallback / setConditionEvaluator
22 * - 临时断点（3）：setTemporaryBreakpoint / clearTemporaryBreakpoint /
23 * getTemporaryBreakpoint
24 * - 状态查询（11）：getBreakpointHitCount / getBreakpointKind / getLogpointMessage /
25 * getFunctionBreakpoints / hasFunctionBreakpoint / getFunctionBreakpointHitCount /
26 * getFunctionBreakpointCondition / isExceptionBreakpointEnabled /
27 * getExceptionBreakpointHitCount / hasWatchpoints / getCallStack
28 * - 生命周期（2）：stop / reset
29 *
30 * 不纳入接口的部分（各子类提供，Facade 层分派）：
31 * - 步进操作：DebugController.stepIn/stepOver/stepOut/resume vs
32 * VmStepper.stepByMode(VmStepMode)
33 * - 状态快照：DebugController.getVariableSnapshot vs
34 * VmStepper.getStack/getGlobals/getCurrentFrameLocals
35 * - 内部 hook：DebugController.checkBreak(ASTNode*) vs
36 * VmStepper 私有 checkBreakpointHit(int)
37 * - VM 独有：setCompileResult / setUseRegister / getCurrentIP / getFrameCount / ...
38 * - Interpreter 独有：setBreakpoint(int) / toggleBreakpoint / setVariableCallback / ...
39 *
40 * 与 IBackend.h 的关系：
41 * IBackend 抽象执行后端（Interpreter/VM/RegisterVM），IDebugController 抽象调试控制器
42 * （DebugController/VmStepper）。两者正交，一个执行后端可对应一个调试控制器。
43 *
44 * @since P1-4
45 */

55// IDebugController 调试控制器抽象接口（P1-4）
56// ============================================================
57// 设计目标：为 Interpreter 路径（DebugController，跨线程阻塞）与 VM 路径
58// （VmStepper，主线程异步）提供统一的类型契约，使上层 Facade（IdeController）
59// 可通过 IDebugController* 统一操作断点配置与状态查询，无需类型分发。
60//
61// 继承关系：
62// - DebugController : public QObject, public IDebugController
63// - VmStepper : public QObject, public IDebugController
64// （QObject 不参与接口继承，避免 moc 钻石继承问题；IDebugController 是纯抽象类）
65//
66// 与 Facade 层的关系：
67// IdeController 当前按组合持有 DebugCoordinator + VmStepper 具体类，
68// 通过双写（配置类）+ 分派读（查询类）覆盖全部场景。提取接口后行为不变，
69// 仅类型契约化，为未来扩展（如 JIT 调试器）预留统一操作路径。
70//
